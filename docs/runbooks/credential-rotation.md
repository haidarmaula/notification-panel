# Rotating notification credentials

Record the environment, applications, affected process replicas, old and new key **identifiers**, approved change window, backup dependencies and rollback decision in the restricted change record. Keep private material, raw destinations, tokens and passphrases in the designated secret store. Each process loads a protected policy at startup. Replace a mounted bundle atomically and roll the affected roles. Existing processes keep their in-memory configuration until they exit.

## Delivery and receipt overlap

1. Inventory the live database and retained recoverable backups. On the live database, run the [key dependency query](../../scripts/sql/key-dependencies.sql) in one read-only snapshot. The query needs read access to the referenced identifier, status, version and time columns. Use a trusted schema and a statement deadline appropriate to the database. For a local production-schema example run `PGOPTIONS='-c default_transaction_read_only=on -c search_path=pg_catalog,public -c statement_timeout=15000' psql -X --set=ON_ERROR_STOP=1 --file=scripts/sql/key-dependencies.sql service=notification_inventory`. The service profile must use the intended database and verified TLS. An incomplete query gives no retirement evidence.
2. For address encryption, generate a fresh AES-256 key under a previously unused positive version. Distribute both decryption versions to every mobile API and delivery worker that handles the application. Keep the fingerprint HMAC key identical across every application that shares a provider namespace. A fingerprint-key change alters conflict detection and requires a separately reviewed migration with writers fenced. Keep the old encryption version active for writing until every reader has both versions.
3. For receipt signing, distribute the new Ed25519 public key to every enabled API for the application. Give the scoped worker the corresponding private key alongside retained private keys. Keep one stable key ID per key and environment. Use synthetic delivery/receipt canaries to verify both public keys before switching the worker's active `receipt_key_id`.
4. Switch the active encryption version and receipt signing ID in the writer policies. Verify a pre-change installation can refresh, a conflicting enrollment is still rejected, and a changed destination creates a generation under the new version. Confirm a previously charged delivery keeps its original signing ID and expiry, a fresh reservation uses the new ID, and a late authorized receipt can still be recorded. Keep both generations available through a rollback. Reverting to an older binary that only understands the old ring can strand new ciphertext or reports.
5. Repeat the dependency inventory after all old writers exit. `retained` includes retired bindings and frozen receipt metadata. `pending` counts outstanding delivery intents pinned to each key. `active_bindings` counts destinations still eligible for use. `unexpired_capabilities` and `last_expiry_unix` cover the database's frozen receipt scopes, including scopes whose device report has yet to arrive. The counts include every application in the connected schema. No rows on one database says nothing about another deployment, backup or downstream archive.
6. Retain old encryption keys for all ciphertext and recoverable backup generations under the approved access policy. Keep the old public verification key throughout the accepted observation and restore/reconciliation windows. Keep the old private signing key available wherever pending deliveries may legitimately reuse frozen metadata. Review all these conditions before retiring an identifier. With a suspected compromise, hold new dispatch, revoke the affected IAM/key trust under the incident authority and reconcile rejected reports and uncertain sends before reopening.

## Other credential families

| Credential | Transition and verification |
| --- | --- |
| FCM service account | Keep the worker's approved project, route and service-account identity fixed. Issue a fresh authorized credential, update the protected file, and restart a bounded worker cohort. Verify OAuth and an authorized test-device send with the new credential before disabling the superseded key. Record provider audit/key IDs and whether previously minted access tokens remain usable. The SDK simulation checks the request path locally. Actual IAM and device proof require the target environment. |
| Staff access and refresh | Follow the [staff session policy](../specs/staff-sessions.md) for independent purposes and current DB session checks. Exercise pre-change and post-change login/refresh, logout, reused refresh and offboarding. A key rotation alone cannot reapply a post-backup session revocation. |
| Mobile identity and origin | The current project policy pins one public key for each purpose. Coordinate issuer switchover and token reissuance with the mobile identity owner. During an incompatible transition, hold mobile mutations until both parties verify their new policies. Verify the project, subject, issuer, audience and origin nonce rejection on the replacement bundle. |
| Gateway, monitors and Kafka mTLS | Install the trust chain for the new leaf at both ends before rotating a leaf. Check gateway identity and peer allowlist, monitor scraping or broker role/ACL canaries as applicable. Retire the old trust only after connected and reconnecting clients pass. Exercise removal with a denied certificate. |
| Database, bootstrap and retention | Distribute a scoped replacement login or client credential to its own role and drain old pools. Verify grants and negative access checks with the new identity. Restrict bootstrap material to the provisioning job. Preserve the separately controlled recovery and retention operator identities. |

## Local acceptance

The integration suite exercises rotating binding generations against a live database, the dependency report, frozen receipt metadata after takeover, and failure before provider credential acquisition when an old decryption/signing key is missing. Use `GOFLAGS='-race -run=TestKeyInventoryDuringBindingRotation$|TestReceiptMetadataStableAcrossTakeoverAndRotation$|TestSubmissionMissingRetainedKeysNeverReachesTransport$|TestObservationReauthorizesOriginalOwnerAndFrozenKey$|TestFirebaseSDKAgainstSimulation$' bash scripts/integration.sh` against the disposable fixture. Actual secret manager permissions, backup key availability and credential retirement require separate target evidence.
